# MCU 基板（core-XIAO-04）要件書（案）

新しい電源基板（基板A / 基板B）と、改版する mother-ring（`mother_ring_redesign.md`）に合わせて、MCU 基板を作り直すための要件書。
mother-ring のヘッダ割り当ては MCU 基板と同時に決めるため、**MCU 基板を先に固める**（2026-10-10 合意）。回路図・PCB はまだ触らない。

現状の調査元は `FPC-isolation-sphere/kiban/core-XIAO-03`（KiCad）、ファームの `src/BoardConfig.h`、`docs/xiao_bringup.md`。

状態：**案**。§5 の未決事項、特に MCU への給電（§3）が決まるまで、回路図は始めない。

## 2. 電源基板の側から来る要件

| 項目 | 内容 |
| --- | --- |
| 給電 | `3V3_MCU`（3.3 V、1〜2 A クラス）。基板A の MCU 降圧から、LTC2954 が制御する。mother-ring 経由で来る |
| 電源制御 | `PWR_KILL`：MCU → 基板A（LTC2954 KILL）。通常のシャットダウンに使う |
| LED 電源制御 | `LED_EN`：MCU → 基板A（LED 降圧の EN）。起動時は Low |
| 電源の ON 検出 | `HALL_WAKE` は北極 → 基板A の LTC2954 に直接つながり、**MCU 基板には来ない** |
| 北極センサ | TMAG5273 を I²C で読む（コマンド、通常の電源 OFF ジェスチャ）。ホール入力の GPIO は不要 |
| I²C | 100 kHz で立ち上げる。基板B の充電 IC と残量計（BQ25792、BQ28Z620）にも同じバスで届く |

### 2.1 ファームの前提との食い違い

`docs/xiao_bringup.md` の「確定した方針」は、旧電源（PCA9632 で `VETO` / `PWR_OFF` を出し、ホール入力を GPIO で読む）が前提。新電源では次のように変わる。

| 旧 | 新 |
| --- | --- |
| PCA9632 の ch0 = `VETO`、ch1 = `PWR_OFF`（I²C） | `PWR_KILL`（GPIO、基板A のプルアップ付き）。`LED_EN`（GPIO） |
| ホール入力 GPIO（短押し / ダブル / 長押し） | TMAG5273（I²C）。電源 ON は DRV5032FC → LTC2954 のハードウェア |
| ハードの長押し OFF 約 1.5 秒 | LTC2954 の強制 OFF 約 7.8 秒（最小 5.5 秒） |

MCU 基板の改版と並行して、ファーム側の方針（`xiao_bringup.md` の次にやること 1〜3）を見直す必要がある。

## 3. MCU への給電（最優先の未決事項）

旧設計は、5 V（`VIN`）を XIAO の 5V ピンに入れ、XIAO 内蔵のレギュレータで 3.3 V を作っていた。新設計では `3V3_MCU`（3.3 V）が直接来るため、そのままでは入れ方が定まらない。

Seeed の XIAO ESP32S3 の資料には、次のように書かれている（[Getting Started](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/)）。

- 3V3 ピン：「onboard regulator の regulated output」。700 mA まで取り出せる。**外から 3.3 V を入れてよいかは書かれていない**。
- 5V ピン：USB の 5 V が出る。入力として使えるが、外部電源との間にダイオード（ショットキーなど）が必要。
- 内蔵レギュレータの型番・入力範囲は書かれていない。

3.3 V を内蔵レギュレータの入力（5V ピン）に入れても、ドロップアウトのため 3.3 V は出ない見込み。3V3 ピンに外から入れる場合、USB が同時につながったときの逆流・競合と、レギュレータの出力側からの逆流の可否を、XIAO の回路図で確認する必要がある。

候補：

| 案 | 内容 | 懸念 |
| --- | --- | --- |
| A | `3V3_MCU` を XIAO の 3V3 ピンに直接入れる | 資料に記載がない。USB 接続時に電源が競合する。レギュレータの出力側からの逆流を確認する |
| B | 基板A に 5 V の MCU 用レールを追加し、5V ピンに入れる（ダイオード付き） | 基板A の設計変更。降圧が 1 段増える |
| C | 3V3 ピンを使わず、MCU 基板上に電源切替（理想ダイオードなど）を置き、USB 接続時は外部給電を切る | 部品が増える。XIAO の 3V3 ピンの出力と衝突しないか確認する |
| D | XIAO をやめて、ESP32-S3 のモジュールを直接載せる | 設計の規模が大きい |
| E | XIAO 裏面の BAT パッド（単セル電池の入力）に給電する（2026-10-10 ユーザー案） | 下記 §3.2 |

### 3.1 調べた結果（2026-10-10）

公式の回路図（[XIAO_ESP32S3_SCH_v1.1.pdf](https://files.seeedstudio.com/wiki/SeeedStudio-XIAO-ESP32S3/res/XIAO_ESP32S3_SCH_v1.1.pdf)）は、この環境から読めなかった（ダウンロードが遮断され、取得ツールでも本文が取れない）。**内蔵レギュレータの型番と、3V3 ネットへの逆流経路は未確認**。回路図の PDF を添付してもらえれば確認できる。

代わりに、Seeed のフォーラムで次の情報があった。いずれも公式の仕様ではない。

- 3V3 ピンへの外部給電について、[Seeed の担当者は SAMD21 版の XIAO で「できるが勧めない」と答え、VIN を使うよう勧めている](https://forum.seeedstudio.com/t/can-i-connect-an-external-3-3v-power-to-the-3v3-pin/272174)。ESP32S3 版についての回答は見つからなかった。
- [別のスレッド](https://forum.seeedstudio.com/t/board-supplied-3-3v-power-vs-usb/260195)では、3V3 ピンに外から給電して USB をつなぐと競合するかという質問に、担当者の回答はなかった。投稿者の1人は、USB の VBUS が 5V ピン（VIN）に直結していて内蔵 LDO に入ること、3V3 ピンはレギュレータで USB の 5 V から分離されていることを述べている。新しい版では 5V ピン側のダイオードが外されたという、Seeed の担当者の回答を引用した投稿もある。
- 同じスレッドで、内蔵レギュレータを取り外して外部レギュレータを付けた人がいる（改造）。

追加の情報（ユーザー提供、2026-10-10）：[tsuzureya.net のレビュー（**XIAO ESP32C3**）](https://tsuzureya.net/review-seeed-studio-xiao-esp32c3/)に、「3.3Vピンに3.3Vを供給しても動作しますが、この場合はバッテリーへの充電は行われません」とある。ディープスリープ中の消費は、3.3V ピン給電で約 70 µA、5V ピン給電で約 200 µA（内蔵レギュレータの待機電力と LED の差と推測）。
- これは **C3 版** の記述で、S3 版の保証ではない。測定時に USB を同時に接続していたかは書かれていない。
- 少なくとも C3 版では、3V3 ピン給電が実際に動くことと、内蔵レギュレータを通らないぶん待機電力が小さくなることが分かる。

分かること：案 A（3V3 ピンに直接入れる）は、公式に保証された使い方ではないが、C3 版では動作の報告がある。案 B で 5V ピンから給電すると、新しい版ではダイオードがなく、USB ホストへ電流が逆流する可能性がある（MCU 基板側にダイオードが必要）。案 D（ESP32-S3 モジュールを直接載せる）は、この種の問題が出ない。

おすすめの順序：回路図を確認する → 案 A を使う場合は、**手元の XIAO ESP32S3 で次を実測する** → 問題があれば、案 C（MCU 基板での電源切替）か案 D。

案 A の実測項目（S3 版）：
1. USB なしで、3V3 ピンだけに 3.3 V を入れて起動し、Wi-Fi 送信時のピーク電流でも 3V3 が安定するか（`3V3_MCU` のリップルを測る）。
2. 3V3 ピンに 3.3 V を入れたまま USB をつなぐと、どちらの電源が主になるか。USB 側（VBUS）に電流が出ていかないか、3V3 側に電流が逆流しないか（電流計を `3V3_MCU` に直列に入れて測る）。
3. 起動順序：基板A が `3V3_MCU` を入れるタイミングで、XIAO が正常に起動するか。
4. 運用の取り決め：USB を差すのは、電池電源を切った状態（`3V3_MCU` が出ていない状態）に限る、という手順で足りるか。足りるなら、MCU 基板に保護回路を足さなくてよい。

### 3.2 案 E：BAT パッドからの給電

XIAO ESP32S3 には、裏面に電池用の BAT パッドがある。Seeed の資料では、BAT の入力は 4.2 V（単セルのリチウム）、USB 接続時の充電電流は 100 mA、電源管理チップが内蔵されている（[Getting Started](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/)）。BAT は「外から電源を入れる」ために用意された入口なので、3V3 ピン（出力用）や 5V ピン（ダイオード必須）より、入れ方として筋が良い。

利点：
- 外部電源を入れる正規の入口である。USB の 5 V と 3V3 ピンが競合する問題を避けやすい（電源管理チップが両方を切り替える設計と思われる。要確認）。
- 電池の入力として設計されているので、3V3 ピンのような出力ピンへの逆給電にならない。

懸念（いずれも回路図で確認が要る）：
1. **電圧が足りない可能性**：BAT の範囲は単セルの電池（概ね 3.0〜4.2 V）。`3V3_MCU` の 3.3 V をそのまま入れると、内蔵レギュレータの電圧降下で 3V3 が 3.3 V を下回る恐れがある。ESP32-S3 の動作下限（約 3.0 V）に近づく。電圧を 3.6〜4.0 V 程度にした専用レールを作るなら解決するが、基板A の降圧が 1 系統増える。`VSYS`（6.0〜8.4 V）は 4.2 V を超えるので直接は入れられない。
2. **USB 接続時の充電**：USB をつなぐと、内蔵の充電回路が BAT に電流（最大 100 mA）を流し込む。この電流が基板A の降圧の出力に入る。降圧がシンク（吸い込み）できないと、軽負荷時に電圧が上がる。MCU 基板側にダイオードを入れると逆流は防げるが、電圧がさらに下がる。
3. **電池なしの扱い**：電池がないと判断して、内蔵 LED が点滅する（資料の「charging LED」）。見た目の問題だけの可能性が高いが、確認する。
4. **機械**：BAT パッドはモジュールの裏面にある。MCU 基板の上に XIAO を面実装する場合、パッドの位置に対応するランドを基板に置ければ配線が要らない。core-XIAO-03 のフットプリント（`XIAO-RP2350`）に BAT パッドの位置が入っているかを確認する。

判断：電圧（懸念 1）が成否を決める。回路図で内蔵レギュレータの型番とドロップアウトを確認し、`3V3_MCU` のまま入れられるか、専用レールが要るかを決める。専用レールが要るなら、案 D（ESP32-S3 モジュールを直接載せる）と手間を比べる。

## 4. 改版の要件

### 4.1 信号とピン

| 信号 | 方向 | XIAO のピン | 備考 |
| --- | --- | --- | --- |
| LED データ 1〜4 | MCU → ring | D0〜D3（GPIO1〜4） | 従来どおり |
| LED データ 5 | MCU → ring | D7（GPIO44）または他 | 回路図とファームの食い違いを直す（§1.1）。RMT は 4ch なので 5 本目は時分割 |
| `I2C_SDA` / `I2C_SCL` | 双方向 / MCU → | D4 / D5（GPIO5 / 6） | 従来どおり。IMU（J9）と ring の両方に出す |
| `PWR_KILL` | MCU → 基板A | D8〜D10 のいずれか | ストラップピン（GPIO0 / 3 / 45 / 46）と USB（19 / 20）、UART0（43 / 44）は避ける。起動中は High-Z（FW-1） |
| `LED_EN` | MCU → 基板A | D8〜D10 のいずれか | 起動中は Low。基板A のプルダウンでデフォルト OFF |
| ブザー | MCU → LS1 | D6（GPIO43） | 起動時のノイズに注意。残すかを決める |
| SPI（J3） | — | D8〜D10 | 未使用。`PWR_KILL` と `LED_EN` にピンを譲るなら削除する |

案：`PWR_KILL` = D8（GPIO7）、`LED_EN` = D9（GPIO8）、D10（GPIO9）は予備。

### 4.2 ring とのコネクタ（J2、J4 の置き換え）

`mother_ring_redesign.md` §6-2 の案：

| ピン | J2 側（旧 ESP32-01） | J4 側（旧 ESP32-02） |
| ---: | --- | --- |
| 1 | `GND` | `GND` |
| 2 | `3V3_MCU` | `GPIO01`（LED データ 1） |
| 3 | `I2C_SDA` | `GPIO02` |
| 4 | `I2C_SCL` | `GPIO03` |
| 5 | `PWR_KILL` | `GPIO04` |
| 6 | `LED_EN` | `GPIO05`（LED データ 5） |

- MCU 基板と ring は向かい合うため、座標は鏡像になる（`mother_ring_redesign.md` §3.1）。現状の SDA / SCL の入れ替わりが意図したものかも、ここで確認する。
- 現状のヘッダは MCU 基板の x = ±22.54（張り出し）にあり、ring では y = ±22.54。2 枚は約 90° 回して重ねる配置になっている。新しいコアで、この向きを維持するかを決める。
- GND が 1 本ずつに減る。電流は小さい（MCU とセンサのみ）ので足りる見込みだが、LED データの帰還と I²C のノイズを考えて、追加の GND を取れるか確認する。

### 4.3 電源まわり

- 旧 5 V 系（`VIN`、電源表示 LED の R1 / D1、C3 / C5 / C6 / C8 / C9、J1、J6、J15、`TP_VIN`）は、給電方式（§3）に合わせて整理する。電源表示 LED は `3V3_MCU` に付け替えるか、削除する。
- `PGND` と `AGND` は FB1 でつながっている。新設計の `GND` は ring・基板A とも共通の 1 ネットなので、MCU 基板でも分けるかを決める（電源側と信号側を分ける利点が実際にあるか）。
- `3V3_MCU` の入口に、デカップリングとテストポイントを置く。
- I²C のプルアップ（R2、R3、10 kΩ → `3V3`）は現状 MCU 基板上にある。位置と電源ドメインを決める。基板B には `3V3_MCU` が OFF でも給電されたままのデバイスがある。SDA / SCL を経由する逆給電を作らない（`interfaces.md` §3）。
- `PWR_KILL` は、基板A の 100 kΩ プルアップに任せ、MCU 基板に別のプルアップ・プルダウンを置かない。リセット中・起動中に Low を出さない GPIO を使う。

### 4.4 機械

- 外形は 40 mm 角 + 左右の張り出しを基本に、新しいコアの寸法（再設計中）に合わせる。
- 浮き・抜け対策（別途対応済み）に必要な取付穴などがあれば、その方針に合わせる。
- 部品面と、ring に向く面を決める。

## 5. 未決事項

1. **MCU への給電方式**（§3 の A〜D）。XIAO の回路図で、内蔵レギュレータと逆流経路を確認してから決める。
2. `PWR_KILL` と `LED_EN` に割り当てるピン（§4.1 の案でよいか）。
3. LED データ 5 本目のピン（GPIO44 のままでよいか）と、GPIO3（D2、ストラップピン）を LED データに使い続けてよいか。
4. ブザーを残すか。SPI ヘッダ（J3）を削除してよいか。
5. IMU（J9）の位置と、I²C の本数（ring に出す分と別に必要か）。
6. 外形・張り出し・ring とのコネクタの向きを、新しいコアの寸法に合わせて確定する。
7. 作図ツール：KiCad のまま改版するか、EasyEDA Pro に移植するか。
8. ファーム側の方針（`xiao_bringup.md` の PCA9632、ホール入力 GPIO）を、新電源（`PWR_KILL`、`LED_EN`、TMAG5273）に合わせて見直す。

## 6. 作業の順番

1. 給電方式（§3）を決める。XIAO の回路図を確認する。
2. ピン割り当て（§4.1、§4.2）を決める。ここで ring の J8 / J9 の割り当ても決まる。
3. core-XIAO-03 を `core-XIAO-04` として複製し、回路図を改版する（給電、`PWR_KILL`、`LED_EN`、不要部品の削除）。
4. 外形・コネクタ位置を新しいコアに合わせ、配線し直す。DRC と、`fit_check.py` による収納確認。
5. 決まったピン割り当てを、`mother_ring_redesign.md` とファーム（`BoardConfig.h`）に反映する。
